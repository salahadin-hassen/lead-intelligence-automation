          02

          Processing rules
        

        
Validation first. Routing second.

        

          Responsibilities are cleanly separated: FastAPI manages intake verification and scoring, while n8n manages workflow branches and audit logs.
        

      


      

        

          01 / VALIDATE
          
Strict schema validation

          
FastAPI requires name, valid email format, company, message, and source. Invalid requests return HTTP 422 before any lead is stored.

        


        

          02 / DEDUPLICATE
          
Composite duplicate protection

          
A repeated source and external ID pair returns HTTP 409 Conflict instead of creating redundant records in PostgreSQL.

        


        

          03 / SCORE
          
Resilient intent scoring

          
FastAPI uses LLM scoring when available, automatically falling back to deterministic heuristics if provider requests fail.

        


        

          04 / DISPATCH
          
Deterministic qualification

          
n8n enforces the 70-point qualification threshold, records the event in audit tables, and triggers notifications accordingly.

        04
        /
        Operational behavior
      


      

        

          
Production boundaries and operational expectations.

          

            
Working sandbox prototype

            

              This public demo operates on cloud sandbox environments. Instances may sleep when idle and require a brief wake period on the initial request. Use synthetic information only.
            

          

        


        

          

            
Authenticated internal API

            
Internal FastAPI endpoints require valid Bearer token authorization, rejecting unauthenticated traffic with HTTP 401.

          


          

            
Predictable error semantics

            
Malformed submissions return HTTP 422 with field-level details. Duplicate submissions return HTTP 409 Conflict.

          


          

            
Scoring resilience

            
Leads receive scores even during provider outages through local fallback algorithms, ensuring intake never stalls.

          


          

            
Synthetic data notice

            
Submissions are stored in the demo PostgreSQL database for testing and demonstration purposes.
