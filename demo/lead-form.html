Enterprise Readiness

Built For Reliability Under Pressure

Designed with defensive distributed system principles: idempotent ingest, fail-open scoring, and decoupled notifications.

🛡️

PostgreSQL Idempotency

A composite unique constraint on source and client external ID guarantees that re-transmissions and network retries never generate ghost leads or duplicate CRM records.

🤖

Dual-Engine Scoring

Configurable OpenRouter LLM evaluates buying intent against a 0–100 rubric. If the LLM provider fails or times out, a local deterministic heuristic takes over seamlessly.

📲

Telegram & WhatsApp Dispatch

High-priority leads trigger instant mobile alerts via Telegram and WhatsApp Business Cloud API. Downstream messaging errors never drop or delay the intake HTTP 201 response.

🔒

Privacy By Design

Free-text customer messages are stripped before triggering external webhook alerts. Only sanitized metadata (name, company, email, score, lead ID) travels to external messaging apps.

📊

Audit Trail Persisted

Every scoring decision, qualification threshold check, and notification outcome is recorded in n8n's execution history for complete operational observability.

⚡

Zero-Framework Frontend

Self-contained vanilla HTML5/CSS/JavaScript with zero third-party CDNs or tracking scripts. Fast initial paint, responsive down to 320px mobile screens.

Engineering Highlights

Fault Isolation & Defensive Architecture

Clear boundaries between edge proxy, orchestration engine, database, and notification buses.

⚡ Pipeline Execution Order

  • Webhook Ingestion: n8n captures inbound JSON payload and formats schema.
  • Early Response: Respond Created issues HTTP 201 to caller before async notification dispatch.
  • Audit Persistence: Execution record is generated regardless of external channel availability.
  • Parallel Delivery: Telegram and WhatsApp notification branches run concurrently with isolated error boundaries.

🛡️ Failure Resilience Matrix

  • LLM Provider Down: Automatically falls back to deterministic heuristic rules (0-100).
  • WhatsApp API Quota/Outage: Logged as operational failure; Telegram continues uninterrupted.
  • Duplicate Submission: Caught at database layer; n8n translates to clean 409 Conflict.
  • Schema Violation: Pydantic rejects invalid types with detailed 422 Unprocessable Entity.
